# Импорт исторических данных из Excel

Одноразовый (но идемпотентный) импорт данных 2026 года из Excel-файлов
Виктории в БД приложения.

## Запуск

```bash
npm run import:excel
```

Скрипт: `scripts/import-excel.ts` (tsx, переменные из `.env.local`, нужен `DATABASE_URL`).
Файлы-источники читаются из `/Users/olegkozyrev/Downloads/Бюджет-эксель`
(путь задан константой `SRC_DIR` в начале скрипта).

Скрипт **идемпотентен**: в начале в одной транзакции выполняется
`TRUNCATE transactions, amortization_accruals, asset_adjustments, cap_movements,
cap_goals, assets, fund_movements, account_snapshots, obligations RESTART IDENTITY CASCADE`.
Справочники (categories, accounts, income_sources, fund_categories, settings) не
очищаются; из них изменяются только `opening_balance`/`monthly_plan` статей КС и
добавляются служебные записи «(импорт) …» через `ON CONFLICT DO NOTHING`.
Повторный запуск полностью пересобирает операционные данные.

Если какое-то название строки Excel не находится в словарях маппинга, скрипт
**останавливается с понятной ошибкой** (`ИМПОРТ ОСТАНОВЛЕН: …`) до записи в БД —
ничего не «угадывается».

## Источники

| Файл | Лист | Что берём |
|---|---|---|
| `Months/0.1.1_March_26_B.xlsx` … `0.2.0_August_26_B.xlsx` (6 файлов, март–август) | «Месяц» | операционные расходы, переводы, компенсации из КС, сбережения, поездки |
| — те же файлы | «Баланс» | строка «На начало месяца» → снимки остатков |
| `Amortization/0.2.0_Amortization_26_B.xlsx` | «Амортизация 2026» | реестр активов, покупки, цели КАП («Ац по месяцам» не импортируется) |
| — тот же файл | «Детализация КАП» | только контрольная сумма для отчёта (движения не импортируются) |
| `0.1.0_Income_26_B.xlsx` | «Доходы» | доходы по месяцам |
| `0.1.0_STS_26_B.xlsx` | «КС» | входящие остатки, планы и движения фонда КС |
| `0.1.0_consolidated_budget_26_B.xlsx` | «Сводка» | **не импортируется** — только сверка итогов в отчёте |

Игнорируются: `~$*.xlsx`, шаблоны (`*template*`), папки «Старые версии».

## Маппинг

### Лист «Месяц»

Строка 1 — номера дней в колонках C..AG; колонка A — названия строк, колонка B — итог
строки. Блоки определяются по заголовку в колонке A (позиции строк не хардкодятся,
пустая строка завершает блок).

- **Операционные блоки** (Питание, Красота, Транспортные расходы, Бабушки, Прочее,
  Поездки и путешествия) → `transactions kind='expense'`, счёт «Т-Банк дебетовая»
  (упрощение: реальный счёт оплаты в Excel не фиксировался), дата = день колонки.
  Различия названий сведены словарём: «Ежемес. деньги» → «Ежемесячные деньги»,
  «Уходовая косметика (лицо и тело)» → «Уходовая косметика», «Подписки, интернет,
  моб. связь» → «Подписки, интернет, связь», «Химчистка и ремонт одежды» → «Химчистка»,
  «Всё для дома и уборки» → «Всё для дома», «Эл. книги и канц. товары» → «Эл. книги и
  канцтовары», «Совсем прочее» → «Совсем прочее (+КУ)», поездки: «Питание» → «Питание
  в поездке», «Жилье» → «Жильё».
- **Ячейки-формулы** вида `=2360+648+847-211` разбиваются на отдельные транзакции по
  слагаемым (минусовые — отрицательная сумма-возврат); произведение `2800*2` считается
  одним слагаемым (5600). Скобки допускаются только как аддитивные группы. Если формулу
  разобрать нельзя или сумма слагаемых не сходится с вычисленным результатом — берётся
  одно значение-результат (фиксируется в отчёте; в финальном прогоне таких не было).
  Примечание ячейки (threaded comment — читается напрямую из XML xlsx, exceljs их не
  парсит) попадает в `note` первой транзакции ячейки с префиксом `[импорт]`.
- **«Покупки»** → транзакции НЕ создаются (покупки приходят из реестра амортизации);
  суммы месяца сверяются с purchase-транзакциями реестра в отчёте.
- **«Амортизация»** → не импортируется (начисления генерятся из реестра активов).
- **«Переводы»**:
  - «КАП» → transfer дебетовая → «НС КАП»;
  - «КС» → transfer дебетовая → «НС КС»;
  - «Временный вклад» → transfer дебетовая → счёт «Временный вклад (импорт)»
    (создаётся: `type='deposit'`, `deposit_kind='interest'`, source = дебетовая);
  - «Снятие наличных» → transfer дебетовая → «Наличные ₽»;
  - «Расходы наличными» → `expense` со счёта «Наличные ₽», категория «Совсем прочее
    (+КУ)», note `[импорт] расходы наличными` (категорий в Excel не было);
  - «Другое» → transfer дебетовая → «Выданные долги», note `[импорт] другое`;
  - отрицательная сумма в ячейке перевода = возврат: счета меняются местами, note
    `[импорт] возврат` (пример: возвраты временного вклада в марте/апреле).
- **«Компенсировано из КС»** (Волосы; Косметология и лазер; Бабушки; Х/ч и ремонт
  одежды; Прочее) → пара: `transactions kind='reimbursement'` со счёта «НС КС» +
  `fund_movements kind='reimbursement'`, `settle='from_account'`,
  `offset_applied_at=NULL`, сумма движения отрицательная, связаны `transaction_id`.
  Статьи фонда — **служебные**, созданные импортом: «(импорт) Волосы», «(импорт)
  Косметология и лазер», «(импорт) Бабушки», «(импорт) Х/ч и ремонт», «(импорт)
  Прочее» (группы Красота/Красота/Бабушки/Прочее/Прочее, `monthly_plan=0`), чтобы не
  искажать реальные статьи из STS. Эти же расходы фонда присутствуют в «израсх.» листа
  «КС» — то есть на уровне фонда это **осознанный дубль**: реальные статьи в точности
  повторяют STS, а служебные держат банковскую сторону. Виктория потом разнесёт вручную.
- **«Сбережения»** → `transactions kind='saving'` с дебетовой на счета: «Драг.
  металлы» → «Драгоценные металлы», «Фондовый рынок» → «Фондовый рынок», «Наличные
  рубли» → «Наличные ₽», «Долгосрочный вклад» → «Долгосрочный вклад Т-Банк»,
  «Наличные доллары» → **«Доллары (по цене покупки)»** — служебный счёт
  (`type='brokerage'`, `currency='RUB'`), создаётся импортом: суммы в Excel рублёвые,
  а счёт «Наличные $» ведётся в USD, класть рубли на него нельзя. Отрицательная сумма
  (изъятие из сбережений, напр. −49 686,92 с долгосрочного вклада в мае) сохраняется
  отрицательным saving — балансы считаются корректно.

### Лист «Баланс»

Строка «На начало месяца» (ищется по тексту), шапка колонок B..K сверяется с ожидаемой
(при несовпадении — стоп): Т-Банк деб., Т-Банк кредитка, КАП, КС, временные вклады,
наличные ₽, наличные $, драг. металлы ₽, долгосрочный Т-Банк, долгосрочный ВТБ.
Ненулевые значения → `account_snapshots(on_date = 1-е число месяца)`.
Фактически снимков 21: март (6 счетов), апрель (8), май (6), июль (1 — драг. металлы);
июнь и август в Excel не заполнены (нули), колонка «наличные $» нигде не заполнена.

### «Амортизация 2026»

Блоки категорий определяются по строкам-заголовкам в колонке B («Одежда», «Красота и
здоровье», «Техника», «Прочее», «Книги, блокноты, канцтовары» → категория «Книги»,
«завершено»). Для каждой строки-актива (B наименование, C дата покупки, D цена,
E срок, K «отложено», M целевая сумма, N статус):

- `assets`: `initial_price` = сумма **положительных** слагаемых формулы цены;
  каждое отрицательное слагаемое (`=29431-2208`) → `asset_adjustments` с reason
  `[импорт] зачёт/продажа` датой покупки. Эффективная цена = вычисленный результат D.
  Для блока «завершено» категория актива не восстановима — ставится «Прочее» с note
  `[импорт] завершено`; `disposed_at` не ставится.
- `transactions kind='purchase'` полной эффективной ценой в дату покупки, категория
  «Покупки → <категория>», счёт «Т-Банк дебетовая», привязка к активу.
- `amortization_accruals` генерятся `buildSchedule(эффективная цена, дата, срок)` —
  значения из Excel не переносятся (Σ начислений точно равна эффективной цене).
- **КАП**: если N ≠ «не применимо» и M — число → `cap_goals` (target = M из Excel,
  `inflation_rate=1.1`, monthly = M/срок). Для статуса «потрачено»
  `spent_at` = дата покупки + срок; если эта дата в будущем — ставится `2026-04-01`
  (7 таких целей, перечислены в отчёте прогона). `cap_movements`: одна запись
  `source='recalc'` c amount = K («отложено», вычисленное значение), date `2026-04-01`,
  note `[импорт] отложено по Excel`; для потраченных — вторая запись `source='spend'`
  с −K тем же днём (леджер цели = 0). Помесячные взносы и перетоки из «Детализации
  КАП» **не** восстанавливаются (данные слишком грязные) — переносится агрегат;
  из «Детализации» берётся только контрольная сумма (SUBTOTAL пополнений − списаний)
  для сверки: в финальном прогоне леджер БД **300 979,94 ₽ = контролю** копейка в копейку.

### «Доходы»

Строки-листья (включая блоки «Прочее» и «Доходы наличными», у которых значения в самой
строке блока) → `transactions kind='income'`, **дата = 15-е число месяца** (точных дат
в Excel нет — середина месяца), `counter_account` = «Т-Банк дебетовая» («Доходы
наличными» → «Наличные ₽»). Формулы с многими слагаемыми не разбиваются — одна
транзакция на строку на месяц. Маппинг источников: М/м 1/2 → Машиноместо 1/2,
«Возврат долга за ВиВи» → «Возврат долга», ВТБ и «Т-Банк % по вкладам» → «Проценты по
вкладам», оба кэшбека → «Кэшбек», все 4 строки «% по НС» → «Проценты по НС»,
«Ежемесячный платеж» → «Ежемесячный платёж», остальные по одноимённым источникам.
Импортируются все месяцы с данными: **февраль–август** (февраль есть только в доходах,
расходных файлов за февраль нет).

### «КС» (фонд)

Статьи маппятся на засеянные `fund_categories` («санаторий Аня» → «Санаторий Аня»,
«д/р Аня/Зина» → «День рождения …», «встречи» → «Встречи», «На др» → «На дни
рождения» и т.д.). Текстовые числа с неразрывными пробелами («248 196», «7 500»)
нормализуются. Обновляются `opening_balance` = колонка C, `monthly_plan` = колонка D.
Движения по парам колонок E..AB (янв–дек): «отл.» → `plan_topup` (+X, 1-е число),
«израсх.» → `reimbursement` `settle='from_account'`, `offset_applied_at=NULL`
(−X, 15-е число). **Без банковских транзакций** (`transaction_id NULL`) — банковские
переводы на КС уже импортированы из месячных файлов. Поэтому сверка счёта «НС КС» и
фонда расходится на сумму рассинхрона Excel — это ожидаемо (вопрос №9). Импортируются
все заполненные месяцы, включая будущие плановые «отл.» (сентябрь) — так сальдо статей
в точности равно колонке B Excel.

## Допущения и упрощения

1. Счёт всех операционных расходов и покупок — «Т-Банк дебетовая» (в Excel счёт не фиксировался).
2. Даты доходов — 15-е число месяца (условные).
3. Даты движений фонда КС — 1-е («отл.») и 15-е («израсх.») числа (условные).
4. «Наличные доллары» из сбережений идут на служебный рублёвый счёт «Доллары (по цене покупки)», а не на USD-счёт «Наличные $».
5. Компенсации из КС в месячных файлах ложатся на служебные статьи «(импорт) …» — дубль «израсх.» из STS на уровне фонда (разнести вручную).
6. Временные вклады — один служебный счёт «Временный вклад (импорт)» (в Excel это одна колонка «временные вклады Т-Банк»).
7. Цели КАП: агрегат «отложено» одной записью `recalc` на 2026-04-01; помесячная история не восстанавливается. `spent_at` для потраченных = покупка+срок, при будущей дате — 2026-04-01.
8. Активы блока «завершено» получают категорию «Прочее» (реальная категория в Excel не указана) и note `[импорт] завершено`.
9. Формулы переводов/сбережений/компенсаций не разбиваются на слагаемые — берётся значение ячейки целиком (разбиение только для расходных ячеек).
10. Блок «Амортизация» месячных файлов и лист «Ац по месяцам» не импортируются; «Детализация КАП» — только контрольная сумма.
11. Поездки импортируются как обычные расходы с категориями `row_type='trip'` в даты ячеек (годовая логика поездок — на стороне приложения).

## Итоги финального прогона (21.08.2026)

Записано: **742 транзакции** (expense 518, income 74, purchase 91, reimbursement 21,
saving 5, transfer 33), **91 актив**, 21 корректировка активов, **2544 начисления**
амортизации, **90 целей КАП** (25 потрачено; без цели — 1 актив «не применимо»),
91 движение КАП, **183 движения фонда** (162 из STS + 21 компенсация), **21 снимок**
остатков. Σ начислений = Σ purchase-транзакций = 1 363 472,75 ₽ (сходится точно).

Сверка (полный отчёт печатается при каждом прогоне):

- **Расходы**: «сопоставимая» величина (БД без поездок − расходы наличными − разница
  покупок реестр/Excel) совпадает с B3 месячных файлов и со строкой «фактические»
  consolidated **копейка в копейку** по всем 6 месяцам.
- **Доходы**: БД = строка «Итого доходы» Excel по всем месяцам (февраль–август) точно.
- **Поездки**: БД = B73 Excel точно (май 892 182,65; июнь 57 160; июль 111 396,60).
- **Фонд КС**: сальдо каждой реальной статьи и итог (280 697,00 ₽) = колонке B Excel точно.
- **КАП**: леджер целей 300 979,94 ₽ = контрольной сумме «Детализации КАП» точно;
  «отложено» recalc 360 900,55 ₽ = SUBTOTAL пополнений.
